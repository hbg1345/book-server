회원, 도서 검색, 장바구니와 주문 기능을 제공합니다. 아래에서 기능별 요청 형식과 응답 예시를 확인할 수 있습니다.

실행 요청은 배포된 Cloud Run 서버로 전송됩니다. 결제·환불 연동은 Stripe 테스트 환경이며 프론트엔드는 구현하지 않았습니다.

처음 사용한다면 — 회원 가입과 주문 순서
  1. 회원 가입: POST /api/users로 계정을 생성합니다.
  2. 로그인: POST /api/auth/login 응답의 accessToken을 복사합니다. 아래 Authorize에 토큰 값만 입력합니다. Bearer는 자동으로 붙습니다.
  3. 도서 검색: GET /api/books의 title에 제목을 입력합니다. 검색 결과의 bookUuid를 사용합니다.
  4. 장바구니 추가: POST /api/cart/items에 도서 식별자와 수량을 전달합니다.
  5. 주문 생성: POST /api/orders에 등록된 배송지의 addressUuid 또는 직접 입력한 address 중 하나를 전달합니다. 성공하면 purchaseUuid를 반환하고 장바구니가 비워집니다.
  6. 결제 요청·상태 확인: POST /api/orders/{purchaseUuid}/payment-intent로 테스트 결제 요청을 생성합니다. 이 호출만으로 결제가 완료되지는 않습니다. 결제 수단 확인 후 Stripe의 성공 알림을 받아 주문 상태를 반영하며, GET /api/orders/{purchaseUuid}로 상태를 조회합니다.
인증·관리자 권한과 오류 응답 읽는 방법

회원 가입, 로그인·토큰 갱신·로그아웃, 도서·저자 조회는 회원 인증 없이 호출할 수 있습니다. 장바구니·배송지·내 주문은 회원 인증이 필요합니다. 도서·저자 변경과 배송 준비·발송·배송 완료 처리는 관리자 권한이 필요합니다. 일반 회원 가입으로 관리자 권한이 부여되지는 않습니다.

400입력값 오류, 빈 장바구니 등. detail과 필드별 errors를 확인합니다.
401 / 403인증 실패 / 권한 부족. 인증·권한 오류는 응답 본문이 없을 수 있습니다.
404대상이 없거나 본인이 접근할 수 없는 주문·배송지입니다.
409중복 정보, 재고 부족 또는 허용되지 않는 주문 상태 변경입니다.
502외부 결제·환불 요청 처리에 실패했습니다.

각 API의 Responses에는 테스트에서 확인한 상태 코드와 실제 응답 예시를 표시합니다.
